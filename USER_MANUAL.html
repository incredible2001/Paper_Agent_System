1. 系统简介

Paper Agent System 是一个全自动论文撰写多智能体系统，基于 LangGraph 构建，能够自动完成从需求分析到终稿生成的完整论文撰写流程。

🤖 多智能体协作

9个专业智能体各司其职，协同完成论文撰写

📚 自动文献检索

基于 PubMed API 自动检索和验证参考文献

📝 版本管理

自动保存大纲和草稿的每个版本，记录修改历史

👥 模拟审稿

支持配置审稿人特点，模拟真实审稿过程

流程说明

  1. 需求分析 (Analyst) - 分析用户论文和导师建议，提取结构化需求
  2. 文献检索与验证 (Literature) - 根据论文内容生成 PubMed 检索式、检索文献、验证参考文献
  3. 大纲生成 (Outliner) - 生成论文大纲并保存 v1
  4. 论文撰写 (Writer) - 撰写论文内容
  5. 质量检查 (Checker) - 检查论文质量
  6. 并行审稿 (Reviewer A & B) - 双盲审稿评估（参考审稿人特点）
  7. 决策 (Decision) - 根据审稿意见决定：接受、小修或大修
  8. 大纲更新 - 大修时可能更新大纲至 v2
  9. 翻译 (Translator) - 生成中文版本
  10. 最终输出 - 英文版、中文版、总结报告和大纲版本历史

2. 安装与配置

2.1 环境要求

  • Python 3.10+
  • 网络连接（PubMed API 需要）
  • LLM API Key（OpenAI 或 Anthropic）

2.2 安装步骤

克隆项目

git clone https://github.com/your-repo/Paper_Agent_System.git
cd Paper_Agent_System

安装依赖

pip install -r requirements.txt

配置 API Key

复制 .env.example 为 .env，然后填入你的真实 API Key：

cp .env.example .env

编辑 .env 文件，填入你使用的 API Key：

# MiMo API (默认，推荐)
MIMO_API_KEY=sk-mimo-your-key-here
MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic

# OpenAI API (如果需要用 GPT-4o)
OPENAI_API_KEY=sk-your-key-here

# Anthropic API (如果需要用 Claude)
ANTHROPIC_API_KEY=sk-ant-your-key-here

只需填你实际使用的 API Key：

  • 如果只用 MiMo → 只填 MIMO_API_KEY 和 MIMO_BASE_URL
  • 如果只用 OpenAI → 只填 OPENAI_API_KEY
  • 如果混合使用 → 填多个 Key，系统会根据配置自动调用对应的 Key

配置 PubMed

编辑 config.yaml，设置你的邮箱：

pubmed:
  email: "your_email@example.com"
  api_key: ""  # 可选，提高速率限制

2.3 API Key 与 Provider 的关系

系统会根据 input/llm_config.yaml 中配置的 provider 自动调用对应的环境变量：

Provider 环境变量 示例模型
mimo MIMO_API_KEY, MIMO_BASE_URL mimo-v2.5-pro, mimo-v2.5-lite
openai OPENAI_API_KEY gpt-4o, gpt-4o-mini
anthropic ANTHROPIC_API_KEY claude-3-5-sonnet, claude-3-opus

2.4 常见配置场景

场景1：只使用 MiMo（推荐）

# .env
MIMO_API_KEY=sk-mimo-xxxxx
MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic
# input/llm_config.yaml
defaults:
  provider: "mimo"
  model: "mimo-v2.5-pro"
use_defaults: true

场景2：只使用 OpenAI

# .env
OPENAI_API_KEY=sk-xxxxx
# input/llm_config.yaml
defaults:
  provider: "openai"
  model: "gpt-4o-mini"
use_defaults: true

场景3：混合使用不同厂商

# .env
MIMO_API_KEY=sk-mimo-xxxxx
MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic
OPENAI_API_KEY=sk-openai-xxxxx
ANTHROPIC_API_KEY=sk-ant-xxxxx
# input/llm_config.yaml
use_defaults: false
agents:
  writer:
    provider: "openai"
    model: "gpt-4o"
  reviewer_a:
    provider: "anthropic"
    model: "claude-3-5-sonnet"
  reviewer_b:
    provider: "anthropic"
    model: "claude-3-5-sonnet"
  # 其他用 MiMo
  analyst:
    provider: "mimo"
    model: "mimo-v2.5-pro"
  literature:
    provider: "mimo"
    model: "mimo-v2.5-pro"
  outliner:
    provider: "mimo"
    model: "mimo-v2.5-pro"
  checker:
    provider: "mimo"
    model: "mimo-v2.5-pro"
  translator:
    provider: "mimo"
    model: "mimo-v2.5-pro"

注意事项：

  • 不要泄露 .env 文件，它已在 .gitignore 中被排除
  • 确保 API Key 有足够的额度
  • 如果遇到 API 调用失败，检查 Key 是否正确配置

3. 快速开始

创建新项目

python main.py --new-project my_paper

这会从模板创建一个新项目目录。

准备输入文件

编辑 projects/my_paper/input/abstract.txt，粘贴你的论文摘要。

摘要格式建议包含 Title、Background、Methods、Results、Conclusions 等部分，系统会自动解析。

运行工作流

# 自动模式
python main.py --project my_paper --mode auto

# 手动模式（需要在决策节点手动选择）
python main.py --project my_paper --mode manual

查看结果

运行完成后，查看 final/ 目录：

  • *_final.docx - 英文终稿
  • *_final_zh.docx - 中文终稿
  • 修改总结报告_v*.md - 修改总结

5. 输入文件说明

5.1 abstract.txt（必需）

论文摘要，系统会从中提取标题、研究背景、方法、结果、结论和参考文献。

推荐格式：

Title: 你的论文标题

Abstract:

Background: 研究背景...

Methods: 研究方法...

Results: 研究结果...

Conclusions: 研究结论...

Keywords: 关键词1, 关键词2, 关键词3

References:
1. 作者. 标题. 期刊. 年份.
2. 作者. 标题. 期刊. 年份.

5.2 advisor_feedback.txt（可选）

导师或合作者的修改建议，系统会将其纳入需求分析。

5.3 draft.docx（可选）

已有的论文草稿（Word格式），系统会在此基础上进行修改。

5.4 reviewer_a_profile.txt / reviewer_b_profile.txt（可选）

审稿人特点描述，详见第9节：审稿人特点配置。

6. 配置详解

6.1 全局配置 (config.yaml)

# LLM 配置 - 多模型支持
llm:
  # 全局默认模型
  default_model:
    provider: "mimo"          # 提供商: mimo, openai, anthropic
    model: "mimo-v2.5-pro"
    temperature: 0.7
    max_tokens: 4096

  # 提供商配置
  providers:
    mimo:
      api_key_env: "MIMO_API_KEY"
      base_url_env: "MIMO_BASE_URL"
    openai:
      api_key_env: "OPENAI_API_KEY"
    anthropic:
      api_key_env: "ANTHROPIC_API_KEY"

  # Agent 专属模型配置（可选）
  agents:
    writer:
      provider: "openai"
      model: "gpt-4o"
    # ... 其他 agent

# PubMed 配置
pubmed:
  email: "your@email.com"
  max_results: 20

# 工作流控制
workflow:
  max_inner_loops: 1
  max_outer_loops: 2
  decision_mode: "manual"

6.3 LLM 配置文件 (input/llm_config.yaml)

这是最灵活的配置方式，可以在 input/ 目录下创建此文件来为每个 Agent 指定不同的模型。

快速配置：只需修改 defaults 部分即可为所有 Agent 设置同一模型。

# 全局默认设置
defaults:
  provider: "mimo"
  model: "mimo-v2.5-pro"
  temperature: 0.7
  max_tokens: 4096

# 是否使用全局默认设置
# true: 所有 agent 使用 defaults（除非单独指定）
# false: 使用各 agent 的独立配置
use_defaults: true

# Agent 专属配置（可选）
agents:
  writer:
    max_tokens: 16384  # 写作需要更多 token
  translator:
    max_tokens: 16384  # 翻译需要更多 token

6.4 混合使用不同厂商模型

7. 运行工作流

7.1 CLI 命令

命令 说明
python main.py --list-projects 列出所有项目
python main.py --new-project <name> 创建新项目
python main.py --project <name> 运行项目（手动模式）
python main.py --project <name> --mode auto 自动模式运行
python main.py --project <name> --mode manual 手动模式运行

7.2 运行模式

自动模式 (auto)

  • 系统根据审稿意见自动决策
  • 两位审稿人都给出"接受/小修" → 直接通过
  • 任一给出"大修" → 返回修改
  • 达到最大循环次数 → 停止

手动模式 (manual)

  • 在决策节点暂停，显示审稿意见
  • 用户选择下一步操作

7.3 决策选项（手动模式）

选项 说明
revise 大修后重新提交审稿
accept_with_minor 小修后直接接受
reject 终止流程
auto 切换为自动模式继续

7.4 运行监控

运行过程中会输出各节点执行日志。日志文件位置：

  • system.log - 全局日志
  • projects/<项目名>/运行日志.log - 项目日志

8. 输出文件说明

8.1 outlines/ - 论文大纲

保存论文大纲的每个版本，包含版本信息和修改记录。

{
  "version": 1,
  "timestamp": "2026-05-28T10:30:00",
  "change_reason": "初始大纲生成",
  "outline": {
    "title": "论文标题",
    "sections": [...]
  },
  "changes_summary": {
    "title_changed": false,
    "sections_added": [],
    "sections_removed": [],
    "sections_modified": []
  }
}

8.2 literature/ - 文献列表

PubMed 检索到的文献列表，包含期刊分区信息。

8.3 drafts/ - 中间草稿

每次撰写/修改的草稿 JSON，用于回溯和调试。

8.4 reviews/ - 审稿意见

两位审稿人对每版草稿的审稿意见。

8.5 final/ - 最终输出

  • *_final.docx - 英文终稿
  • *_final_zh.docx - 中文终稿
  • 修改总结报告_v*.md - 修改总结报告

8.6 state_snapshots/ - 状态快照

每个节点完成后都会保存状态快照，用于调试和回溯。

9. 审稿人特点配置

9.1 配置方式

支持两种配置方式（二选一，文件优先）：

方式一：配置文件

在 project_config.yaml 中：

reviewer_profiles:
  reviewer_a: |
    这位审稿人重视研究设计的严谨性
    对统计方法要求严格
    倾向于给出 major_revision
  reviewer_b: |
    注重结果的临床意义
    重视参考文献的时效性
    倾向于给出 minor_revision

方式二：输入文件（推荐）

在 input/ 目录下创建：

  • reviewer_a_profile.txt
  • reviewer_b_profile.txt

9.2 特点内容建议

可以包括以下内容：

  • 审稿风格偏好 - 倾向于给出什么类型的审稿结论
  • 关注的重点领域 - 创新性、方法论、结果解读等
  • 历史审稿意见 - 以往审稿中常提出的问题
  • 常见的修改建议 - 对特定类型研究的偏好
  • 对特定方法的偏好 - 统计方法、实验设计等

9.3 示例

审稿人A特点：

1. 研究设计
- 非常重视RCT设计的严谨性
- 关注样本量计算的依据
- 要求详细的随机化和盲法描述

2. 统计方法
- 要求明确主要终点和次要终点
- 关注亚组分析的合理性
- 期望看到敏感性分析

3. 审稿风格
- 倾向于给出 major_revision
- 意见详细且具体
- 通常需要2-3轮修改

审稿人特点会被注入到审稿人的 prompt 中，影响其审稿风格和关注点。如果不配置，审稿人会使用默认的通用审稿风格。

10. 大纲版本管理

10.1 自动版本管理

系统会在以下时机保存大纲：

  1. 初始大纲生成 → outline_v1.json
  2. 大修后更新 → outline_v2.json（如果审稿建议调整结构）

10.2 大纲修改触发条件

  • 审稿人明确建议调整论文结构（如"建议增加XX章节"）
  • 质检报告指出结构问题
  • Writer 在修改时主动调整

10.3 大纲 JSON 结构

{
  "version": 1,
  "timestamp": "2026-05-28T10:30:00",
  "change_reason": "初始大纲生成",
  "outline": {
    "title": "论文标题",
    "sections": [
      {
        "heading": "Introduction",
        "level": 1,
        "key_points": ["要点1", "要点2"],
        "estimated_words": 500,
        "related_references": [1, 2]
      }
    ]
  },
  "changes_summary": {
    "title_changed": false,
    "sections_added": [],
    "sections_removed": [],
    "sections_modified": []
  }
}

10.4 大纲 diff 示例

{
  "changes_summary": {
    "title_changed": false,
    "sections_added": ["Limitations", "Future Directions"],
    "sections_removed": [],
    "sections_modified": ["Discussion"]
  }
}

大纲更新需要审稿意见中包含明确的结构调整建议。系统会自动识别关键词如"建议增加"、"应该删除"、"需要重命名"等。

11. 常见问题

Q1: PubMed 检索失败

原因：邮箱未配置或网络问题

解决：

# config.yaml
pubmed:
  email: "your_real_email@example.com"

Q2: LLM 调用失败

原因：API Key 未配置或额度不足

解决：

  1. 检查 .env 文件中的 API Key
  2. 检查 API 额度
  3. 尝试更换模型

Q3: 运行太慢

解决：

# config.yaml
pubmed:
  max_results: 5  # 减少文献数量

workflow:
  max_outer_loops: 1  # 减少循环次数

Q4: 生成的内容有错误

原因：LLM 幻觉

解决：

  • 在 abstract.txt 中提供详细的数据和结果
  • 使用 advisor_feedback.txt 指出需要修正的地方
  • 使用手动模式，在决策节点审阅后决定

Q5: 大纲没有更新

原因：审稿意见未明确建议结构调整

说明：大纲更新需要审稿意见中包含明确的结构调整建议，系统会自动识别并更新。

Q6: 如何重新运行某个项目

解决：

# 删除状态快照（可选）
rm -rf projects/<项目名>/state_snapshots/*

# 重新运行
python main.py --project <项目名> --mode auto

for project in project1 project2 project3; do
